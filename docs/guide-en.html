AI coding agents are only as good as the rules they get. This kit gives both agents the same rules, safe permissions and three ready workflows, so every session starts the way your team works.

What you get

One rules file for both agentsAGENTS.md holds how to run, test and finish a task. Codex reads it directly; CLAUDE.md imports it with one line.
Safe permissionsTests and git diff run without asking. push and commit ask first. Force-push and reading .env are denied.
A guard for secretsA hook blocks any edit to .env, keys and credential files, and tells the agent to ask a person.
Three skills/pr-review finds bugs before the PR. /release-notes writes notes a client can read. /sop-from-notes turns notes into a process document.

Set up in 10 minutes

  1. Copy AGENTS.md, CLAUDE.md and the .claude/ folder to your repo root.
  2. Fill the 3 placeholders in AGENTS.md: what the project is, how to run it, how to test it.
  3. Put your own test and lint commands in the allow list of .claude/settings.json.
  4. Open Claude Code in the repo once and accept "trust this folder".
  5. Type /pr-review. In Codex, ask "what are the rules for this repo?" to confirm it read AGENTS.md.
The rule that saves the most time: make the agent end every task with "tests pass + 3-line summary + what was skipped". You review a summary, not a wall of code.

Write your own skill

A skill is a folder with a SKILL.md: a name, a one-line description of when to use it, and numbered steps. Start from the task your team repeats every week, write the steps the way you would explain them to a new hire, and keep it under 30 lines.

What changes for the team

BeforeEach person prompts differently. The agent guesses how to test, edits files nobody asked for, and someone finds a secret in a commit.
AfterSame rules in every session, risky commands ask first, secrets are blocked, and repeated work is one command away.
